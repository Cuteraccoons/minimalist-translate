# 1.0.4 详细实施计划

更新：2026-09-24。本文是接手模型的逐步工作单，不是已完成功能清单。产品源码本轮未新增百科修复；本轮交付调查与计划。B 编号对应百度百科，W 编号对应维基百科。每次只认领一个小任务；任务中发现别的问题，先记录，不顺手重构。

## 0. 每次开工的固定步骤

1. 阅读工作区 AGENTS.md、源码 HANDOFF.md、本计划第 0/1 节、当前任务小节及对应调查样本。无需每次通读所有其他任务或整个 content.js，先按函数名定位。不要从长聊天记录猜版本，也不要改 archive。
2. 在源码目录运行 `git status --short`、`git log -3 --oneline`，记录起点提交和已有未提交修改；保留别人的修改。确认 manifest 为 1.0.4 候选，不自行升级。
3. 按任务给的网址打开原网页。记录最终 URL、日期、语言、网页加载状态。遇到验证页、网络错误、空内容时记 unavailable；不能用错误页面验证提取器。
4. 找到本任务涉及的原始 DOM。记录容器、父子关系、语义属性、尺寸和短标签，区分隐藏内容、导航、正文。不要保存整篇受版权保护正文或私人数据。
5. 用加载当前源码的原生扩展开启阅读模式。采集对应输出节点及位置，写一条“源内容 A → 实际输出 B → 期望 C”。不能仅靠类名存在就判通过。
6. 做最小 fixture：用自有短文本复现同一结构，保留真实问题需要的嵌套、CSS、属性，不复制整站。至少包含一个应保留案例和一个不应误保留的相邻案例。
7. 先运行 fixture 确认问题真的复现，再改任务指定函数。源码无需修改则明确写“已覆盖，仅补验证”；不可为了产生代码而改正常行为。
8. 修改后重启测试浏览器加载最新内容脚本。跑 fixture、指定真实样本和一个相邻类型对照。将结构正确与视觉待人工确认分开记录。
9. 跑任务级回归、发布审计、翻译核心审计及 `git diff --check`。如果涉及翻译，注明模拟响应还是真实服务；不得借真实服务测试发送无关全文。
10. 在任务表记录日期、提交号、结果和限制，做单项提交。只提交自己的文件。失败未解决就保留“进行中”，不标完成。没有发布授权时不操作商店。
