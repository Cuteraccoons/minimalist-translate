# 后续任务清单

每一步如何执行见 [详细实施计划](IMPLEMENTATION-PLAN.md) 第 2 节；本文件保留任务摘要与样本入口。

全部任务目前未完成。按单项推进，每项一个小提交；先复现，再修改。真实页面链接见 [调查矩阵](BAIKE-SURVEY.md)。代码行号会变化，使用函数名搜索。不要为完成任务而修改统计口径。

## B01 · 基本信息语义与布局（优先）

- 样本：周杰伦、水、杭州市、清华大学，覆盖人物、科学、城市、机构。
- 入口：`content.js` 的 `collectReaderContentNodes`、`readerBaikeBlockHtml` 中 facts 分支；`reader.css` 的基本信息规则。
- 操作：比对源 DT/DD 与阅读器每个字段，检查不紧邻的配对、一个标签多个值、长链接、折叠字段。先保存最小自有文本 fixture，避免依赖整页全文。
- 验收：样本已采集字段分别 24/23/19/29 项无串位；名称、值、链接一一对应。窄正文下长值换行，标签不压缩到逐字竖排，没有重复“基本信息”。源结构变化时更新期望并说明理由。
- 不做：作品卡、时间轴、全局字体重构。

## B02 · 顶部目录与左栏定位

- 样本：苹果公司（137 个采集标题）、周杰伦、民法典。
- 入口：`readerHeadingLevel`、`collectReaderContentNodes`、`openReaderMode` 的标题生成、sourceAnchors 与大纲点击。
- 操作：检查源标题级别、ID/name/data-index 与生成 head_n 的映射；源目录不进入正文，但不能因此删除正文中的同名标题。
- 验收：每页抽查首、中、末和三级标题；点击行尾也跳转正确，目标标题在可视区且不被顶栏遮挡；同名标题不全部跳第一项。三行以上大纲文字不裁下划线。保留缩进到行尾的点击范围。
- 不做：把原网页完整目录再复制到阅读器开头。

## B03 · 表格与图片归属

- 样本：苹果公司优先，其次杭州、周杰伦；证据 `baike-apple-table-audit.json`。
- 入口：`collectReaderContentNodes` 表格过滤、`readerInlineHtml`、`readerTableHtml`、`collectReaderMediaEntries`。
- 操作：区分数据表与一行图文布局。跟踪同一源 IMG 是否随表格与独立块各输出一次，按源节点归属消重。复查 2–80 行／12000 字的过滤边界；大表不能无提示整块丢弃。段落内 TABLE/VIDEO 被 inline 清理是代码风险，先做 fixture 证明。
- 验收：苹果公司的 8 个一行图片表有合理的图片／图注输出；已记录的表格图片不再重复成独立段落；合法复用同一 URL 的不同图注仍保留。合并单元格与数据顺序不变，大表可滚动，正文不出现重复表格全文。
- 不做：按 URL 全文去重；凭数字自动生成温度热力图。

## B04 · 作品卡按类型保留关联

- 样本：周杰伦。
- 入口：`readerBaikeBlockHtml` card/gallery 分支、`collectReaderContentNodes` 的作品容器识别。
- 操作：先影视（movie/teleplay），下一小批再音乐，最后综艺/杂志/获奖。按作品容器提取海报、标题链接、日期、角色等实际存在字段，不把所有人名扁平串接。
- 验收：每类型至少 3 条记录逐字段对照；链接仍指向正确作品，演员不串到下一张卡。缺图有简洁文本卡，横竖海报不裁掉内容。记录翻页／未加载作品的边界，不声称已提取隐藏的全部作品。
- 依赖：B03 避免复合内容重复输出。

## B05 · 图集加载与布局

- 样本：故宫、大熊猫、清华大学、中国共产党。
- 入口：`warmReaderLazyContent`、`readerBaikeBlockHtml` gallery、`collectReaderMediaEntries`。
- 操作：区分加载前占位与真实图片，检查轮播克隆、图注和集合嵌套；有界预热，恢复原滚动位置。空图集不留大片空框，可提供原文入口。
- 验收：至少一个多图和一个合集 fixture；同图不同说明不误删，轮播克隆不重复；保留比例，不强制裁切成同高。用户操作不会被长时间自动滚动阻塞。

## B06 · 时间线／大事记（先调查，后实现）

- 当前证据不足：样本有历史章节，但尚未确认独立时间轴组件。先从苹果公司、秦始皇、长征及其他明确带大事记的词条寻找真实结构。
- 第一阶段交付：可访问的精确 URL、所在章节、日期节点与事件节点的 DOM 关系、是否需要展开、是否 iframe、原始顺序及至少 3 个事件的短标签。找不到时记录“未确认”，不要造选择器。
- 第二阶段入口：`collectReaderContentNodes` 注册特殊块，`readerBaikeBlockHtml` 增加有证据的语义类型。
- 验收：日期与事件一一对应、同日多事件保持顺序、链接可用；无日期事件不得推算年份；窄屏单列、宽屏也保持阅读顺序。普通历史段落保持段落，不强行抽成时间线。
- 不做：恢复用户明确允许跳过的互动图鉴／星图。

## B07 · 正文视频、地图与其他媒体

- 样本：水、光合作用、故宫、清华大学。
- 入口：`openReaderMode` 顶部 videoCover 处理、`readerBaikeBlockHtml` video、媒体统计。
- 操作：检查正文内 data-module-type=video，不能只抓顶部。可直接使用合法可访问的媒体地址时嵌入，否则保留封面、标题、原文入口。地图保留可理解的静态内容或入口。
- 验收：没有空播放器或失效的伪播放按钮；标题／封面／原文入口关联正确；不自动播放，不引入远程执行脚本，不绕过登录或防盗链。媒体统计只计正文媒体，排除扩展工具栏图标。

## 每项完成后的统一步骤

1. 本地 fixture 验证语义与边界，再用对应真实词条做原生扩展 DOM 检查。
2. 运行发布与翻译核心审计；提取逻辑改动额外运行 `reader104-regression.js`、`regression.js`，组合媒体改动补 `chess-links-citations.js`。
3. 更新本文件该任务：完成日期、提交号、验证结果、已知限制。没有完整验证就标“部分完成”。
4. 不做截图检查。保留维护者视觉抽查；不自动升级版本、发布商店或宣称所有百度词条已兼容。
